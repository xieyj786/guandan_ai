# 独立牌局统计测试程序设计

版本0.2，2026-10-31。启动：`python benchmark_gui.py`。本程序独立于原GUI，不改变游戏规则。

## 目标与参数

支持规则队对规则队、LLM队对规则队及两个不同LLM队。每个策略控制同队两人。LLM使用兼容Chat Completions的HTTPS接口，可分别填写基础地址、模型、密钥；密钥仅保留于内存，不写配置或日志。接口支持情况通过连接测试确认，不能保证所有模型兼容。

常用重复轮数为50、100、500，默认50；也允许输入1～500做小批验证。每轮生成13副不同的四人发牌结果，分别用于级牌2、3、…、K、A。先按原座位策略配置完成13局，再复用对应发牌、级牌和首出座位，交换策略A/B所控制的座位队伍，完成另外13局。策略A原控制座位1、3，换位后控制2、4。换位只交换策略，不移动手牌。

每局独立创建Match，不传上一局结果，不升级、不进贡。每轮结束后生成13副新牌。50/100/500轮分别为650/1300/6500副不同发牌、1300/2600/13000场对局。发牌种子为基础种子加“轮次从0开始×13＋级牌从2开始的偏移”；同一配对共用种子，因此完整手牌和首出位置保持一致。对局可启用红心配，自然牌型统计始终不作替代。

## LM Studio 本地模型

统计窗口中每队“类型”可选规则AI、LLM（云端兼容接口）、LM Studio。选择LM Studio后，默认地址为`http://127.0.0.1:1234/v1`，默认模型为`qwen/qwen3.5-9b`，本地等待时间180秒（允许10～600秒）。API Key输入禁用，本地客户端不会读取或发送云端密钥。切换云端/本地类型会分别保留本窗口中编辑的地址和模型。

先在LM Studio加载模型并启动服务，再点击“测试本地连接”。测试会真正请求约定JSON，不仅是检查端口或模型列表。支持本机回环地址、未启用认证的服务；本地请求使用JSON Schema，模型及后端须支持结构化输出。连接失败时核对模型标识、服务、等待时间和Thinking设置。仅本地队伍不弹云端费用提示；混合云端与本地仍对云端费用提示。

每个模型队控制两名玩家，A/B可分别配置本地模型与规则AI或云端模型。建议先跑1轮26局检查耗时和回退；本地模式保留相同的决策、规则接管与错误分类统计。停止时当前请求可能仍需等待网络超时，等待时间不是整次行动的精确截止时间。

## 牌型统计口径

仅统计每次发牌时四家手中持有的自然牌型，不是实际出牌次数，也不是局中重组后出现次数。红心级牌只按真实花色点数计入，不作百搭。

- 6/7/8炸：某点数在一名玩家手中恰好有6/7/8张，计一次。8炸不拆计7炸或6炸，不按组合数计数。
- 王炸：同一玩家持有两张大王和两张小王，计一次。
- 同花顺：同花色五张合法窗口，包括A2345、23456至10JQKA。每个花色/窗口只计一次，重复实体牌不倍增；六张连续同花牌可产生两个重叠窗口，因此此计数不表示能同时打出的独立牌组数。
- 其他不同牌型可共享实体牌，这是持牌潜力统计，不是互不重叠分组统计。

总次数为所有已完成局四家的合计，平均每局=总次数/完成局数。换位模式同一发牌会统计两次，与“总对局次数”分母一致；不是独特发牌数。取消和失败局不进入胜率和牌型平均，CSV仍保存其已获得的数据。

## 胜率与有效性

以头游所属队伍判胜。完成局数是胜率分母，失败局单独报告，不能记成某队输。零完成局的胜率与平均值为null，界面显示暂无。

按策略身份汇总换位前、换位后和合并的A/B胜率，并按13个级牌分别提供三种口径。换位后减换位前的A胜率差以百分点显示；中途停止时两阶段样本可能不平衡，差值仅供描述。

配对比较仅纳入前后两局都完成的牌组，报告A两胜、各胜一局、B两胜。缺失完整配对数=计划牌组数−完整配对数，另报告仅完成一局的数量。完整轮要求该轮26局全部完成。配对局相关，不报告普通独立样本Wilson区间；后续可增加按发牌组重采样的估计。

LLM失败或非法回答仍由现有DeepSeekAgent回退规则AI。记录LLM决策数、回退次数与发生回退的完成局数；这类结果是混合策略结果，不得标成纯LLM胜率。当前不单独给出剔除回退后的胜率，因为事后剔除也可能引入偏差。

Token用量按接口usage原值记录，不估算费用，不能用决策次数替代平台实际请求计费或Token。每次决策无自动重试，连接测试也可能计费。首次使用建议先跑1轮（26局），核实连接与回退率，再开始大批量。

## Token与运行时长

窗口实时显示总运行时长（包含暂停、局间汇总与日志写入）、实际暂停等待、扣除暂停后的时长，以及当前局号和模型决策等待时间。每完成局平均耗时与剩余时间按扣除暂停后的当前均速粗估，模型负载变化会影响准确度；未完成任何局时不估算。

按策略A/B及总计记录实际请求次数、收到可解析响应次数、累计请求耗时、平均/最长请求耗时，以及接口返回的输入、输出、总Token、思考Token、缓存命中Token。请求耗时是HTTP请求到完整JSON响应的端到端时间，含排队/提示处理/生成/传输，并非纯推理时间或纯生成速度。思考是输出的子项，缓存命中是输入的子项，不重复加到总Token。

Token只采用响应usage中有效非负整数。不提供的字段显示“未提供”；只有部分请求有用量时，显示已知值及覆盖请求数，不把缺失当零、不按文本长度猜测。失败/取消局与触发规则接管的请求也纳入耗时/Token；网络错误未收到usage时，Token未知，不能据此认为服务没有计算。收到响应不等于动作有效，合法性及规则回退另行统计。连接测试不纳入整批实验数据。

汇总写入summary.json；rounds.csv增加A/B请求次数、耗时与Token列，并保留各Token字段的有效覆盖请求数（未提供的Token列为空）；events.jsonl为每次请求记录纯数值遥测及策略归属，不存请求正文、密钥或原始回复。换位后仍按策略身份归属。运行结束时冻结总计时，之后查看窗口不会继续增长。新数据从更新后新运行开始采集，旧日志不会自动补齐。

## 执行与文件

后台线程运行，主线程处理界面。暂停在动作边界生效，正在进行的API请求不会被撤回；停止保留已完成结果和当前取消局。API请求超时为25秒；系统网络阻塞可能影响实际停止延迟。

每次在用户选择的目录下建立唯一子目录：

- config.json：非秘密运行参数、协议版本、计划局数、队伍标签、策略版本。
- rounds.csv：局号、重复轮次、级牌、配对编号、种子、首出座位（1～4）、是否换位、状态、座位/策略胜者、回合、LLM/回退次数、耗时与自然牌型次数。
- events.jsonl：初始完整手牌和引擎公开事件，供复盘；日志不会传给AI作为隐藏信息。只保存固定LLM成功/回退标识，不写模型原始输出、密钥或请求头。
- summary.json：每局更新的统计快照和最终状态。
- benchmark_log_NNN.txt：结束或手动停止时，在用户选择的日志目录（与本次benchmark时间戳子目录同级）自动生成，编号从001起，已有文件不覆盖。包含程序名称、北京时间开始/结束时间、总时长、全部中文统计汇总、完整参数/汇总JSON和逐局CSV明细；窗口显示报告绝对路径。

进程内支持暂停/继续；关闭程序后不支持断点续跑。停止后可查看已有文件。文件写入失败应停止并在窗口提示，不继续假称结果已保存。

## 实现边界与扩展

benchmark.py负责参数、自然牌型计数、胜率、运行循环和日志；benchmark_gui.py负责窗口与兼容接口适配。复用Match及规则/LLM Agent。程序暂用Match现有内部逐步接口，未来可提取公开step接口。

后续扩展：按发牌组的置信区间、实际出牌牌型统计、单局失败分类、断点续跑、提供商原生接口及策略版本对照。价格与概率参数不得硬编码成未经验证的结论。

## 本地模型性能优化（2026-11-01）

- 所有模型队在只有一个合法动作时直接执行，不请求模型、不运行规则推荐规划；报告和CSV新增自动执行计数，按策略A/B归属，不计入LLM决策或规则回退。多个合法动作仍由模型决策，不删候选动作。
- LM Studio提示使用紧凑JSON及牌张字符串，合法动作用“编号:牌张”表达，空串表示过牌。完整保留手牌实体数、公开牌计数、近16条历史、规则推荐和全部合法动作ID。云端多动作提示保留原格式。序列化改变可能影响模型选择，不能用离线动作一致性代替真实强度验证。
- 总时长增加钟表经过时间（含系统睡眠），单调时钟仍用于运行耗时及请求耗时；分开展示两者与差额，差额也可能受到系统校时影响，不直接等同于精确睡眠时长。
- macOS统计窗口默认勾选“运行期间防止Mac空闲睡眠”，用caffeinate -i，仅在后台测试运行期间持有，结束、停止或错误后释放；不要求屏幕常亮，不修改系统电源设置，也不阻止合盖或用户主动睡眠。其他平台不启用。暂停期间仍属于正在运行的测试，继续持有防睡眠。
- config.json记录llm_policy版本以区分旧测试。旧报告不改写。

## 本地模型第二轮优化与真实验证（2026-11-01）

统计窗口的“LM Studio（实验）”客户端启用speed_mode，普通“LM Studio”保留上一版协议。游戏主窗口的LM Studio客户端默认仍使用原有模式，云端接口不变。统计模式采用：

- 固定系统说明与动态牌局JSON分离；仅使用兼容接口标准messages字段，不附加未经验证的缓存参数。
- 本地牌张以s/h/c/d表示四种花色，X/Y表示小/大王；保留每张重复实体牌。公开牌数量、近16条记录、所有合法动作及其原编号都保留。常规出牌、过牌、接风和出完记录压缩成结构化数组，未知记录仍原样保留。
- 本地统计请求只要求action_id，省去逐次生成理由；日志仍保留选中的动作编号、实际出牌、请求耗时、Token及回退记录。无法据此提供模型的自然语言解释。
- 配置策略标记为lmstudio_packed_prompt_v2、action_only_v1、stable_system_prefix_v1，防止与旧提示混淆。固定系统说明并不代表缓存已生效，必须以服务端实际记录为准。
