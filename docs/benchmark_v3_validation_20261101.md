# 本地LLM第二轮代码优化与26局实测（2026-11-01）

结论：修正版完成26/26局，失败0、取消0、规则回退0。相比上一轮，钟表耗时减少5.36%，总Token减少8.56%；收益有限，不能据单轮认定稳定提速。普通LM Studio保留原提示格式，精简格式通过“LM Studio（实验）”显式选择。

## 改动

- 新增本地精简输入：花色/点数短码、公开牌数量、结构化近期记录，保留全部实体牌、公共信息、候选动作和明确编号。
- 实验模式使用固定system说明与动态user数据，只返回action_id，省去逐次生成解释；普通模式保留原提示与理由。
- LM Studio解码Schema枚举本次真正合法的ID；Agent及规则引擎仍作最终检查。
- 实时累计本局模型决策和回退，不再等一局结束才更新。
- 配置记录协议对应关系，队伍标签区分实验模式；测试源码、解释器和校验清单保存在日志目录。

## 同种子完整26局对比

两个批次均为种子42、级牌2至A、13组同牌换位、启用红心配，策略A为同一本地Qwen模型ID，策略B为规则AI。初始四家手牌、级牌和首出位置已逐局核对一致。模型生成不是确定性的，提示也会改变模型选择，因此不是隔离单个优化因素的严格实验。

| 指标 | 上一轮v1 | 本轮v3 | 本轮变化 |
|---|---:|---:|---:|
| 总时长 | 1:50:13 | 1:44:19 | 减少5.36% |
| 模型请求 | 639 | 681 | 增加6.57% |
| 自动执行唯一合法动作 | 853 | 821 | 对局路径改变 |
| 每请求平均耗时 | 10.335秒 | 9.181秒 | 减少11.16% |
| 输入Token | 508181 | 477365 | 减少6.06% |
| 输出Token | 19973 | 5566 | 减少72.13% |

新协议使每次请求更省，但模型走了不同路线、请求数增加，抵消了一部分收益。前9局实际比上一轮慢4.63%，前13局慢3.96%；后13局更快，整轮才体现5.36%的减少。不能把小样本约29%的请求提速当成整轮收益。

## 完整性与剩余瓶颈

- 完整13组配对；逐局CSV、事件日志、summary与服务端Token总数一致。
- 离线复演26局，公开引擎事件及各局胜者与原记录完全一致；681次调用均有多个合法动作，821次自动执行均只有一个合法动作。
- 服务端681次响应的ID全部处于当次Schema枚举的合法集合内，且输入Token逐次与客户端记录一致。
- 请求累计6252.531秒，占系统运行计时99.90%；其余开销约6.514秒。
- 服务端出现14次缓存命中，共3584 Token，约为输入量0.75%；接口usage未提供缓存字段，不能把服务端结果误填成接口直接上报的数据。
- 以服务端秒级日志粗分，接收请求至最后接近完成的输入处理进度约5942秒，其后约307秒，输入阶段约95.1%。这不是精确GPU计时，说明输入处理仍占主导。
- 请求中位8.733秒、P95约13.027秒、最慢29.080秒。钟表与单调计时差0.016秒，无上次明显睡眠漏计。

## 首次失败试验已保留

v2试验报告benchmark_log_005.txt，完成15局、取消第16局，610请求中出现19次越界编号回退。16次编号恰等于动作数量，另3次对较长列表计数错误。数组隐含下标不适合这次模型交互，已改回显式编号并增加解码ID约束。不能把该部分混合结果当成完整纯LLM测试。

曾有进度更新误称没有回退：当时只看了进度输出而没有读取分类汇总，发现后已向用户更正；同时修复计数仅随完成局更新的显示问题。
