guandan_ai：LM Studio 本地模型接入更新（2026-10-30）

当前项目已集成 LM Studio 本地模型接入，保留“看AI对战”和真人动作闪烁。

运行
1. 在项目原有 Python 环境运行 gui.py；不需要安装新的第三方库。
2. 只更换源码不会更新已有 gui.exe，Windows 独立程序需重新打包。

连接设置
先在 LM Studio 加载 qwen/qwen3.5-9b 并启动本地服务。
在游戏的“LLM设置”中填写：
  服务商：LM Studio
  模型标识：qwen/qwen3.5-9b
  本地API地址：http://127.0.0.1:1234/v1
  本地等待秒数：180（可选10～600秒；这是网络等待值，不是精确的整次行动截止时间）
  API Key：留空；本地模式禁用该输入，不读取DeepSeek凭据。
  LLM玩家：例如AI3，作为您的队友。人机模式中AI1始终由您操作。
点击“测试连接”，收到有效JSON提示后保存，然后在主界面勾选“接入 LLM”。
只有被选座位用模型，其余电脑座位仍用规则AI。
关闭“接入 LLM”恢复规则AI；已发出的请求可能仍在本地计算，旧结果不会执行。

确认是否真的由Qwen出牌
日志会标记“LM Studio”；出现“规则接管”表示本次由规则AI兜底，不能算作模型决策成功。
/v1/models成功只能证明服务可访问；新设置中的“测试连接”还会真正请求模型生成约定JSON。

边界与故障
本版支持同一电脑、未启用API认证的LM Studio服务；不支持局域网模型地址或认证令牌。
本地模型无需云端Token费用，仍占用本机算力和内存。
若连接测试超时，先确认模型已加载、服务已启动；必要时增加等待秒数。
若提示输出截断或正文为空，请检查LM Studio模型设置中的Thinking/Reasoning选项，若可用可先关闭再试。
没有擅自改写模型提示模板，也没有假定DeepSeek的thinking参数适用于Qwen。
本地请求采用JSON Schema结构化输出；具体模型/推理后端支持程度仍以实测为准。
DeepSeek模式保留原有25秒超时、系统凭据和请求参数。

验证
90项自动测试通过（原84项＋6项本地模式测试），包括请求形状、结构化响应、旧配置读取、密钥隔离、错误回退。
测试全部采用模拟请求；本次未执行Qwen真实推理或Tk窗口视觉验收。
运行核心测试：python tests/run_all.py

独立牌局统计窗口（2026-10-31新增）
运行 benchmark_gui.py，选择策略A或B的类型为“LM Studio”。
默认API基础地址：http://127.0.0.1:1234/v1
默认模型：qwen/qwen3.5-9b；可改为LM Studio实际模型标识。
本地等待秒数：180，可输入10～600；API Key禁用，无需填写。
先点击“测试本地连接”，成功后建议输入1轮，共26局试跑。
每队控制两人，可与规则AI、另一队本地模型或云端LLM对战。
本地队不产生云端Token费用；若另一队选云端LLM，云端部分仍可能计费。

2026-11-01 主游戏窗口同步共享LLM改进
1. gui.py自动复用唯一合法动作免调用及合法编号约束；观察与人机模式均适用。
2. LLM设置新增“本地精简模式（实验）”，默认关闭。开启后复用统计窗口已测的显式动作编号、紧凑公开状态和仅编号回复，不生成逐次解释。保存后按原“接入LLM”开关生效。
3. 主窗口新增累计请求、输入/输出/总Token、请求总耗时/平均耗时、自动执行、规则回退和窗口时长。缺失用量不按零估算；统计含重开/暂停后丢弃结果的实际请求，不含设置中的连接测试。新局不清空本窗口累计值。
4. 窗口时长包含暂停、真人等待与系统睡眠，不代表纯模型时间。模型等待时状态栏显示本次已等待秒数。
5. Mac可勾选“LLM运行时防止空闲睡眠”，仅在模型请求未结束或自动观察LLM对战期间持有保护；暂停后待请求完成即释放，退出也释放，不修改系统电源偏好。
6. 原DeepSeek凭据保存格式不变，本地模式不读取云端密钥。旧配置缺少精简模式字段时默认关闭；开启仅影响本地客户端。
7. viewer.py本身为纯规则观察器，没有LLM调用，不额外加入模型接口。旧LLMAgent仍兼容原卡牌JSON协议，但同样跳过唯一动作并检查出牌确属合法候选，非法首出PASS/不能压牌均由规则AI接管。
