## 0 已确认的核心设计原则

以下四条经用户于2026-10-21确认，作为后续实现的设计约束。确认代表认可方向，不表示相关代码已实现、已通过回归或已证明提高胜率。各条细则和阈值仍可根据新牌例修订。

| 编号 | 原则 | 执行含义 | 关联条目 |
|---|---|---|---|
| DP01 | 组牌与出牌一起决定 | 保留不同分组与出牌顺序，根据当前桌面及后续路线选择；不预先固定大炸或小炸方案 | H01、H04、B06 |
| DP02 | 最后一手不要求控场 | 合法出完即取得名次，后续被压不撤销；跟牌时仍必须合法压过当前牌，领出时才不受上一牌型限制 | E05、E06、H04 |
| DP03 | 炸后不好走不等于不能炸 | 后续困难是代价，不是禁令；阻断对手直接收官可优先于自己的顺畅走牌 | B01、B02、B04 |
| DP04 | 拦截允许降低风险，不必保证成功 | 队友控牌时，若对手有眼前走完机会，己方动作能实际降低风险且代价合理，可以盖队友；不要求必定封死 | T01、T02、T08 |

共同边界：先保证合法性，只使用玩家可见信息。残局示例中“忽略其他人出手”只是讨论假设，实际策略必须考虑全部在场玩家。较大单张缩小的是对手可跟出的牌集合，不是已经算出的胜率提升。

本节基于 game_engine/card.py、card_type.py、identify.py、comparator.py、tribute.py、round_result.py，以及 game_series.py。代码与旧文档有差异时在第10节列出，不擅自修改规则。

| 项目 | 本技巧集采用的口径 | 对策略的影响 |
|---|---|---|
| 牌数和队伍 | 两副108张，四家各27张；AI1与AI3、AI2与AI4组队 | 优化团队结果，不以个人最快跑完作为唯一目标 |
| 本局级牌 | 全桌同一个当前级数；两队升级进度单独保存 | 不按玩家所属队伍分别计算牌力 |
| 普通单牌 | 大王＞小王＞级牌＞其余A至2；非级牌2是小牌 | 不使用“有2就能收单”的判断 |
| 基本牌型 | 单张、对子、三张、三带二 | 没有三带一、四带二或任意甩牌 |
| 顺子与同花顺 | 必须恰好5张，不是3至5张，也不能出6张以上 | 不以更长顺子压牌；额外连续牌要分组规划 |
| 顺子点数 | 当前代码支持23456、A2345、10JQKA；不含王；不任意首尾循环 | A2345按5高处理；连续牌按序列而非级牌单张权重比较 |
| 连对 | 固定3组连续对子，共6张 | 不与钢板混淆；跟牌须同组数 |
| 钢板 | 当前支持2组及以上连续三张 | 例如333444；不是334455 |
| 同点炸弹 | 当前类别支持4至8张 | 不建议生成当前未支持的9张、10张炸弹 |

| 红心配 | 本局红心级牌为百搭，不能替王；单出按级牌 | 实体牌与代表牌分开记；不把所有级牌都当百搭 |

## 3 对原问答的修订

### 保留但改成有条件的建议

- 减少手数：同时考虑控制权、难走散牌和队友需求，不能只求牌组少。
- 强牌主攻、弱牌助攻：动态评估，允许互换角色。
- 保留红心配的灵活性：每一步重新比较用途，不强制拖到残局。
- 小炸抢权、大炸控场：是一种常见用途，不是按大小固定出牌阶段。
- 不抢队友牌权：采用用户确定的默认让牌规则，保留一手出完和必须拦截对手两种例外。
- 对手少牌时提高警惕：剩牌数只形成可能结构，不等于确定结构。

### 删除或重写

| 原说法 | 本项目中的替代 |
|---|---|
| 有王或2就能收 | 计算当前级数下的单牌强度，并考虑外部更大牌和炸弹 |
| 三连对就是钢板 | 连续对子与连续三张分别识别 |
| 更长顺子压短顺子 | 只比较合法五张顺子的大小 |
| 成炸牌、核心级牌可以不贡 | 仅依规则保护红心级牌，其他牌不能因结构而逃贡 |
| 接风继续照顾已走队友牌型 | 按自己剩牌和敌方威胁规划名次 |
| 剩六张可能三带二加对 | 那是七张；六张考虑钢板、三连对、六炸或多手组合 |
| 上家或下家固定是队友 | 队友固定对坐；另算跳过出完玩家后的下一行动者 |
| 对手PASS说明没有大牌 | 降低或调整某些猜测的可信度，不作确定排除 |
| 枪不打四、第一顺必炸 | 根据威胁、可替代动作、炸后路线判断 |
| 知道队友手数和具体需要 | 只使用公开信息形成估计，并记录不确定性 |
| 全部候选剪掉就PASS | 回退到原合法候选；领出不能PASS |
| 70%出大牌、30%诱敌 | 暂不固定比例；先建立确定、可解释的基线 |

## 4 统一术语与信息模型

- 剩余张数：手中实体牌的数量。
- 计划手数：某个不重复使用实体牌的分组方案，需要出牌的次数。不是保证实际能走掉的次数。
- 一轮：一次领出到本轮有效牌无人再压、产生下次领出权的过程。
- 控制牌：在特定牌型和当前已知信息下，有较强机会取得或保住牌权的牌。
- 难走牌：需要别人提供牌路、或自己消耗额外牌权才能处理的牌。小点数不必然难走，大牌也不必然好走。
- 自然顶张：同牌型内已知没有更大候选；不代表不会被炸弹压住。
- 一手出完：全部剩牌组成当前合法动作；与“预计下一手可以走”严格区分。

AI精确知道自己的手牌、公开出牌、当前级数、队伍、各家剩牌数、已确定名次和轮转状态。队友及对手未公开手牌不得读取。对贡还牌的跟踪也只使用该玩家合法可见的交换信息。

未见实体牌计数按整副牌减自己手牌、已出牌等互不重叠的已知集合计算；贡还牌只是改变位置，不能当作离开牌局再次扣减。红心配代Q打出时，扣减红心级牌实体，不扣自然Q。

“对手可能剩对子”“队友可能需要单张”属于推断，应有依据、可信程度和失效条件。一次PASS不能排除能压牌或有炸弹；连续PASS也可能是主动保牌。

## 5 适用于本项目的技巧条目

本节是Q与W的有条件改写和D建议；不是声称每条均已实现。括号中的来源说明灵感出处，不表示来源验证了这里的具体判断算法。

### 5.1 组牌与牌力

**H01 多方案组牌，避免开局锁死。** 保留“少手数”“少难走牌”“保控制”“便于配合”几类候选。每次出牌、别人出完或重要控制牌出现后重算。只在某方案所有重要指标均不差时才淘汰另一方案。来源：Q、W5；多方案设计为D。

**H02 配炸要看炸后剩牌。** 多一个炸弹若留下多张无控制的小散牌，未必划算。比较它带来的潜在上手机会与新增走牌负担。来源：W1。

**H03 同花顺不自动最先出。** 它既能走五张，也能用来争夺牌权。若手里仍有难走单张或对子，先比较能否借普通牌路处理，再用同花顺回收。例外：它就是最后一手、明确有利的收官路线，或必须抢先争取团队结果。来源：Q修订、D。

**H04 配大炸不一定胜过配小炸。** 如果炸弹成功取得领出权且剩余牌能够一手出完，不应仅因尾牌较小而额外惩罚该方案（DP02）；如果要先跟普通牌，则剩余组合的强度可能决定能否上手。 比较剩余牌组的质量，而非只看炸弹点数。例如保留一个强三带二，有时比把它的三张配成大炸、留下弱三带二更有价值。来源：W8。不能直接套用原文固定牌力分。

**H05 不把王炸当作必拆或必留。** 王炸保留一次绝对炸弹优势，拆成单王或王对则增加其他控制选择、也可能增加手数。分别比较后续路线；对手仍有大炸时保留王炸可能重要。来源：W5的条件化修订、D。

### 5.2 领出与小牌处理

**L01 普通局面优先比较难走的小组合。** 候选包括不破坏核心结构的小单、小对、小三张、三带二。不要因为某顺子张数多就自动优先，也不要机械地每次出最小单。来源：用户此前目标、Q修订。

**L02 有高单时可考虑先走低单，但不保证回收。** 必须区分王、级牌和非级牌2；同牌型较强也可能遭炸。来源：Q修订。

**L03 没有回收牌的小牌也可能适合先走。** 目的可能是甩掉包袱或把牌权交给队友。要求出后对手风险可接受，而非“不能收就绝不领”。来源：W6。

**L04 弱牌可送小单，强牌保留自己的推进路线。** 延续用户想法：预计自己三手内难走完时，提高送小单的优先级；有较强机会在近期重新取得牌权时，可以按自己的路线走。还要判断队友是否仍在场、对手是否可能直接走掉。三手暂解释为自己的计划出牌次数；“再次拿牌权”的可信阈值待牌例校准。来源：用户既有偏好、D。

**L05 没有固定的“开局对子先行”。** 小对适合保留单张控制或处理对子负担时；若拆坏关键结构，或对手少牌且可能以对子走完，则不应照搬。来源：Q、W7的条件化修订。

**L06 改换牌型只能发生在合法领出时。** 可以领出自己容易走、对手不易跟的类型，但“不易跟”是估计。来源：Q修订。

### 5.3 跟牌与团队配合

**T01 队友控牌时默认PASS。** 当前只保留用户确认的两类例外：自己能一手出完；需要拦截对手。W2提出的“顺便接队友小牌”仅保留为未来实验项，不擅自加入当前默认策略。

**T08 盖队友的风险拦截。** 对手接下来有直接走完机会时，比较PASS与压牌后对手可走牌范围的变化。独立中等单张能降低风险且代价小时，可以倾向压牌，不要求确定封死；拆核心组合时同时比较保留、拆牌和直接出炸的完整路线。若公开信息已排除被拦住的那些牌，则不能把名义上的点数提高当作实际收益。对手仅剩一张而桌面是对子，或队友已出大王时，不触发单张紧急拦截。队友已走完时，应按后续名次与接风重新评估。来源：用户确认DP04；细化阈值待校准。

**T02 最小够用不一定最好。** 对手下家即将走牌时，较大的压牌可能更合适；一般局面则优先避免浪费控制资源和拆散完整牌型。来源：Q、D。

**T03 不重复消耗队伍的控制牌。** 队友的牌已经足够形成压力时，自己再盖更大牌通常收益小。若队友已被对手压住，则不再属于“队友当前控牌”。来源：W2。

**T04 送牌先看实际行动顺序。** 队友需要某类型只是一部分，还要考虑中间对手能否先走、队友是否有机会接住，以及自己是否还保有补救。来源：Q、D。

**T05 不能根据一手出牌断言队友结构。** 队友出对子可能是清理最后一个对子；此前打单也不能证明手中仍有单。每次更新判断。来源：W4、D。

**T06 拆牌送队友只在证据和收益足够时做。** 队友只剩一张能确定其下一次走牌为单张；剩两张不能确定是对子。必要时可拆对、拆三张、甚至拆炸，但比较本队收益与丢失控制的代价。来源：Q修订。

**T07 主攻助攻动态切换。** 队友逼近走完而自己路线变差时可转助攻；自己已形成短且可控的路线时也可转主攻。不要用“牺牲位”永久剥夺弱牌争游机会。来源：W3、D。

### 5.4 炸弹与红心配

**B01 炸之前先评估下一步。** 没有理想后续不能硬性排除炸弹（DP03）；先区别普通抢权、救队友和阻断对手直接收官。 记录炸后准备领出的牌型、剩余手数、难走牌及反炸后的应对。紧急阻断可能必须接受不理想后续，但要说明原因。来源：Q、D。

**B02 比较不用炸弹的替代方案。** 同牌型接住、让下一位仍有机会行动的队友处理、暂时PASS，都应进入比较。不能依赖“队友肯定有牌”。来源：W4、D。

**B03 第一顺只触发评估，不触发必炸。** 是否拦截取决于对手剩牌、后续威胁、本队牌路和所耗炸弹。来源：Q修订。

**B04 对手剩四张不构成禁炸理由。** 既可能是炸弹，也可能是多手散牌。必要时炸能阻断其接下来领出；也可能反而浪费资源，需比较。来源：Q修订。

**B05 小炸也可能要留，大炸也可能要早出。** 大小只是资源强度，不是固定时机。尤其不能因为只有一个大炸而永远不出。来源：W6的条件化整理。

**B06 百搭用途按整手改善比较。** 配同花顺、四炸、扩炸、补顺子、补连对钢板或三带二，都不设一成不变顺序。高层目标是更好的团队走牌路线。来源：Q修订、D。

**B07 单出红心配并非违法或永远错误。** 最后一张、关键封单或明确收官路线都可能合理；一般局面才考虑其机会成本。来源：P、D。

### 5.5 记牌与残局

**E01 全记实体牌，重点解释控制变化。** 已见王、级牌、各点数、各花色及百搭影响可接牌范围。AI不必像人一样只记5、10或王。来源：Q、W4；实体记账为D。

**E02 断张提示可能性，不代表炸弹在某家。** 未见牌数量、每家容量和公开历史共同约束分布；百搭仍可能补炸。来源：Q纠错、D。

**E03 剩牌数决定可能结构，不决定唯一动作。** 对手两张可为对子或散牌；五张可为顺子、同花顺、三带二、五炸或多手牌；六张可为钢板、三连对、六炸或多手组合。来源：Q纠错、D。

**E04 接风后按自己牌路争名次。** 队友已头游时争二游收益最大，但不能为冒险抢二而无视保三价值。若队友不是头游，也要根据当前名次更新团队目标。来源：P、D。

**E05 牌少时比较完整出牌顺序。** 对每个候选考虑“先A再B”和“先B再A”的差别；最后一手能出完后，对手再压牌不会取消已经取得的名次。来源：P、D。

**E06 已经出完的对手不能追回。** 对手最后一手已经打出后，炸它不能撤销其头游，只能影响剩余玩家的牌权与名次。拦截应尽量发生在其最后一次出牌之前。来源：P、D。

### 5.6 进贡还贡

**R01 进贡先守规则，同大候选再谈结构。** 不贡更小牌来保炸。若几张同为最大合格牌，可以比较失去哪张花色对顺子、同花顺结构的损害。来源：P、D。

**R02 还贡先比较自己失去哪张损害最小。** 在2至10的合格集合内，优先评估散牌与结构，而不是永远还点数最小牌。来源：P、W4的审慎改写。

**R03 给谁还贡会改变策略。** 当前单贡在头游与末游同队时也可能发生队内交换；还队友与还对手应分别评价，但都不能读取对方未公开手牌。来源：P、D。

**R04 不假定可以准确阻止对手成炸。** 还某张牌可能帮助对手，也可能没有帮助；只能在信息足够时作概率比较。不能固定排除5、10，更不能为防一个猜测而严重拆坏自己牌。来源：W4的条件化修订、D。

## 6 几个适用于项目的决策例子

下面是局部候选比较，不是完整108张对局，也不声称单凭所列手牌就能确定最优动作。

### 例一 打7时，2不是控制牌

本局打7。小单2若不属于关键组合，可以作为早期处理候选；不能因为“有2”就宣称能回收单张。红心7单出属于级牌，参与组合时另作百搭分析。

### 例二 同花顺和散牌同时存在

本局打7，剩余牌含黑桃34567、一个小单2、一对8和大王。比较先处理小单或对子、保留同花顺取得牌权的路线，与直接领同花顺的路线。不能只因后者一次出五张就选它；若对手即将走完，优先级又可能改变。

### 例三 相同红心配的两种用途

本局打2，有AAA、333、44和一张红心2。在这九张的局部组合中，可以比较A炸加33344与3炸加AAA44；两者均为两手，但留下的三带二强弱不同。还要比较其他分组及外部更大炸弹，不能仅凭A炸更大便选第一种。此例改编自W8，不采用其固定评分。

### 例四 队友控牌，对手只剩一张

队友领出小单，当前轮到自己，下一位对手剩一张。若自己的合法压牌能降低对手直接跟完的风险且代价合理，即使不能确保封死，也可以触发拦截例外（DP04、T08）；如果这手是对子，则剩一张的对手不能跟普通对子，不能套用同样理由浪费炸弹。

### 例五 队友头游后接风

队友最后一手大王，无人在场玩家压牌，自己获得领出权。此时只考虑自己与两名对手的剩余牌和名次，不再研究已出完队友喜欢单牌还是对子。

### 例六 最大贡牌属于四张级牌

本局打5，自己没有王，最大合格牌为非红心5，即使它参与可组成的炸弹也必须从最大合格牌中选贡。可以比较同大5的花色结构损失，不能主动贡A或2代替。

### CASE01 两种两手方案的比较

打2，自己的九张牌为AAA、333、44、红心2。甲为A炸＋33344；乙为3炸＋AAA44。以下子例只改变当前局面，不把对手隐藏牌作为决策输入。

| 子例 | 公开局面与前提 | 预期判断 |
|---|---|---|
| CASE01-A | 当前为对手KKKK | 若决定抢权，甲能压而乙不能；不能只因甲尾牌小而排除 |
| CASE01-B | 当前为对手KKK55 | 比较乙用AAA44普通跟牌、保留3炸，与甲用A炸；乙并不保证拿到下一次领出权 |
| CASE01-C | 自己领出，公开信息足以排除两种炸弹被压 | 两方案均可炸后领出最后三带二；不能仅凭尾牌更大判乙更优 |

关联DP01、DP02。测试应验证候选与判断理由，不把所有信息不完整的局面强行标为唯一最优。

### CASE02 炸后仍有两手难走牌

打7，自己剩4444、88、3。

| 子例 | 公开局面与前提 | 预期判断 |
|---|---|---|
| CASE02-A | 对手出2，仍有很多牌，无紧迫威胁 | 优先比较用3普通跟走，不自动用4444抢权 |
| CASE02-B | 对手出A，仍有很多牌，无救场需要 | 炸后无可靠连续路线，倾向PASS；这不是禁止出炸 |
| CASE02-C | 对手出A后只剩一张；根据行动顺序，自己是阻止其重新领出的最后机会 | 可以出炸阻断直接收官，再比较领88；仍需考虑其他玩家反炸，不声称必胜 |
| CASE02-D | A本身是对手最后一张 | 名次已成立；不能以追回其头游为理由出炸 |

关联DP03、B01、E06。CASE02-C的“最后机会”须由真实轮转状态验证，不能只检查剩一张。

### CASE03 中等单张盖队友

打7，AI3队友出6且仍有手牌，AI4已PASS，轮到AI1，下一家AI2只剩一张。

| 子例 | 自己资源或局面变化 | 预期判断 |
|---|---|---|
| CASE03-A | 有独立Q，公开信息未排除8至Q等牌在AI2手中 | Q不能封住K、A、级牌和王，但可降低风险；代价低时倾向盖Q |
| CASE03-B | 自己剩QQQQ、33 | 比较拆Q、Q炸、PASS；Q炸后仅剩一手是重要优势，但仍考虑其他在场玩家反炸 |
| CASE03-C | 队友实际出K，自己只有Q可作单张 | Q不合法；只能另查合法炸弹或PASS |
| CASE03-D | 队友实际出大王 | 一张牌的对手不能跟出；不因其剩一张而炸队友 |
| CASE03-E | 队友出的是对子 | 一张牌的对手不能普通跟出；不套用单张拦截 |
| CASE03-F | 队友的6是最后一张 | 队友名次已确定；改为比较自己接风、争后续名次和阻止对手走牌 |

关联DP04、T08。例中Q与6之间的可拦点数须按级牌调整：本局7是级牌，不在Q可以封住的普通小牌范围内。实现测试需要补齐实体花色、其他手牌数量、公开历史和轮转记录；本表目前只是牌例规格，不是已运行的测试。

## 7 从技巧到规则 AI 的设计

### 分层职责

| 层 | 负责内容 | 禁止混入 |
|---|---|---|
| 规则层 | 合法牌型、比较、状态转移、贡还、接风、终局 | 为策略方便改变合法性 |
| 信息层 | 公开事件、已见牌、未知分布约束 | 读取队友对手隐藏牌 |
| 规划层 | 合法分组、候选后续路线、控制代价 | 同一实体牌在计划里重复使用 |
| 策略层 | 团队目标、配合、拦截、炸弹取舍 | 把口诀当作无例外禁令 |
| 解释与验证层 | 记录理由、候选、版本及复盘 | 把一次赢牌解释成策略已被验证 |

### 决策流程

1. 获取合法可见信息，判断是领出、跟牌还是贡还阶段。
2. 生成并验证合法候选，保留百搭的有效解释。
3. 优先检查明确的一手出完及即时危险；若已有确定团队获胜方案，不因某条经验扣分而排除。
4. 根据尚未确定的名次设定当前团队目标。
5. 队友控牌时应用默认让牌及两类例外；按DP04允许合理降低风险的拦截，不把“确定封死”作为唯一门槛。
6. 为候选评估剩余手数、难走牌、控制资源、合作收益和对手直接走牌风险。
7. 对接近的候选比较短期后续路线；未知手牌使用受公开信息约束的估计，不能偷看真实状态。
8. 给出动作与理由。策略过滤后为空时退回合法集合，而不是无条件PASS。

不建议先把牌型选死、再只在其中选具体牌，这可能漏掉更好的拆组方案。可按牌型组织候选，但应保留不同类型的合理备选。

### 目标与评分

单副目标以本队名次组合为基础：{1,2}、{1,3}、{1,4}分别对应本队升3、2、1级；{2,3}、{2,4}、{3,4}对应对手升1、2、3级。整场还要考虑当前升级进度和A级结束条件。

手数减少、控制保留、送牌机会等只是过程指标，不能取代名次结果。暂不设定固定“减一手加30分”等权重；权重由牌例和配对对局校准。保留炸弹也不能设成大到永远不愿出炸的奖励。

### 策略条目记录字段

每条保存：编号、名称、来源、状态、适用规则版本、触发条件、可用证据、建议动作、例外、优先级、正反牌例、解释文本及验证结果。

例如T01的解释应为“队友仍控牌，自己不能一手出完，未发现足够强的紧急拦截理由，因此PASS”。不能输出“队友肯定能收”之类未经证实的理由。

## 8 验证与迭代顺序

### 第一阶段 规则与候选正确

对同一手牌，牌型识别、候选生成和动作执行应一致。特别检查百搭补顺子、连对、钢板、三带二，以及相同实体牌的多种解释。识别器支持不等于AI一定会生成该候选。

### 第二阶段 少量明确策略

优先做H01/H02/H03多方案组牌与散牌处理、T01队友让牌例外、B01炸后路线、E04接风残局。保持稳定的旧策略作为比较对象，不同时加入几十条未经验证的经验。

### 第三阶段 推断与短期比较

在记录可靠后，再增加队友需求估计、对手结构估计、短期路线比较。用不确定性而非猜定某家具体手牌。

### 最低牌例集合

1. 同花顺加小单、小对的领出选择。
2. 非级牌2与级牌2的不同判断。
3. 不能使用六张顺子、三带一或普通对子跟单张。
4. 队友控牌时PASS、一手出完、紧急拦截三个分支。
5. 队友剩两张分别是对子或散牌，但AI看到的信息相同。
6. 对手剩四张时炸和不炸各有合理情形。
7. 四王保留和拆分各有合理情形。
8. 红心配扩炸与补普通组合的取舍。
9. 对手最后一手已打出，不能通过炸回去撤销名次。
10. 接风时队友已不在场。
11. 最大贡牌在炸弹中，仍按最大合格牌进贡。
12. 还贡为队友和对手的不同策略；无合格还贡的异常情况。
13. PASS之后仍能在后续机会中合法压牌。
14. 同等点数不可压牌、百搭实体不重复记账。

### 对局评价

相同发牌种子交换策略所属队伍，降低牌运和位置偏差；明确测的是单副还是2到A整场。除胜率外记录升级收益、双上/双下比例、无效动作、策略耗时、炸后无路可走的案例，以及关键规则触发情况。对每条新增策略做启用/禁用对照。

日志需能区分规则AI、真实LLM决策与LLM失败后的规则回退。本轮不实现此前讨论的250局测试窗口。

## 9 优先级与不采纳项

优先：规则口径一致、合法动作完整、团队目标、多方案组牌、可解释的接牌和出炸决策。

后续：公开信息下的概率推断、小规模未知手牌采样、接近候选的混合选择。

暂不采纳：按出牌耗时推断牌力、主动拖延模拟心理战、私有队友暗号、无法解释的固定手数阈值、“枪不打四”“第一顺必炸”等硬禁令，以及来自攻略但无样本依据的胜率或牌型频率。

## 10 当前不足与需要补充的边界

1. 旧rules_design.md仍写顺子不含2，当前identify.py支持23456与A2345。本文按当前实现；后续单独同步文档，不在本轮改变代码。
2. 连对现固定3组，钢板仍支持可变组数，炸弹类别只到8张。本文直接采用，网上其他规则不混入；未来若改玩法应升级规则版本。
3. 当前还贡校验只按牌面2至10，因此低点数红心级牌也合格；是否额外保护它，以及没有合格还贡牌时怎样处理，需要明确补全异常规则。本文不默认新增禁令。
4. “三手内强牌”“可靠回收”的阈值仍待校准；“必须拦截”已由DP04、T08及CASE03细化为眼前危险、实际风险降低与合理代价，但风险估计方法和代价阈值仍待实现验证。
5. 队友需求推断在前期很不可靠，第一版应保守使用。剩牌数不能替代真实结构。
6. 当前规则文档、代码注释和实际行为应建立一份一致的规则基线；策略、日志和LLM提示词都应引用同一版本。
7. 网络资料的经验互有冲突，尚不能证明策略提高胜率。需要保留来源、反例及测试结果，允许撤销无效策略。

本设计建议先把“出牌后剩下什么、谁还能拿到牌权、对本队名次有什么影响”判断清楚，再逐步扩展经验规则数量。


## 11 文档与代码的持续演进约定

### 11.1 稳定编号与状态

DP、H、L、T、B、E、R及CASE编号保持稳定。新增条目使用未占用编号，不因排序改变旧编号；废弃条目保留简短理由和替代编号，便于理解历史日志。

每条分别记录三种状态，不能合并为一个“已完成”：

- 设计状态：待讨论、已确认、已替代。
- 实现状态：待实现、部分实现、已实现、已停用。
- 验证状态：未验证、牌例通过、对局评估完成；保留失败与适用范围，不能笼统标“有效”。

本次DP01至DP04为已确认设计；新增CASE01至CASE03为待补齐测试输入的牌例规格。相关完整实现和验证尚未交付。其余技巧如无独立确认记录，仍是设计建议；原有代码可能实现了其中一部分，不据此自动标为全部已实现。

### 11.2 可扩展条目模板

后续新增或修改条目，按以下字段维护：

| 字段 | 要求 |
|---|---|
| 编号及修订号 | 稳定编号；语义变化增加修订号 |
| 目的与来源 | 解决什么问题，来自用户确认、牌例或资料 |
| 三种状态 | 分别记录设计、实现与验证进展 |
| 适用规则版本 | 引用核实后的规则基线；规则变化时检查适用性 |
| 触发条件与输入 | 明确需要的公开信息；信息不足时如何处理 |
| 建议与例外 | 区分强制合法性、优先考虑和普通加减分 |
| 冲突处理 | 与其他条目的优先关系，不依赖函数调用的偶然顺序 |
| 参数 | 含义、范围、默认值来源；未确定的标待校准 |
| 牌例 | 正例、反例、边界例及关联CASE编号 |
| 实现对应 | 实际文件、函数、测试和日志标识；规划位置注明未创建 |
| 变更记录 | 日期、原因、影响条目、验证结果及回退版本 |

### 11.3 对应代码的扩展方式

以下是未来实现约定，本轮未创建模块或配置功能：

1. 保持Agent对外观测和动作接口稳定。策略只消费合法可见信息，最终动作仍经规则引擎校验。
2. 按职责拆出可独立修改的组牌规划、炸后路线、团队拦截和候选排序逻辑，避免全部堆进一个决策函数；可以先是独立函数，不为扩展性提前堆大量模块。
3. 策略条目使用稳定编号标识，允许逐项启用、停用和替换以作对照；游戏合法性、信息隔离和终局规则不能作为策略开关关闭。
4. 将待校准阈值和权重集中管理，注明含义与有效范围，避免散落在判断中。危险程度改变时调整策略参数，不更改规则引擎的合法性。
5. 每个策略给出候选、依据、代价和建议，不随意删除其他合法路线；中央决策统一处理优先关系。失败或无建议时回退到有效的基线策略，领出不能错误PASS。
6. 日志记录规则基线、策略版本、参数快照或可追溯标识、触发编号、选择理由和随机种子，以便比较和复现。
7. 增加规则时同步新增正反牌例，保留旧用例；修改判断时记录行为为何改变。实验策略效果变差时可停用或恢复旧版本。
